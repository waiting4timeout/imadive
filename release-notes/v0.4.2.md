Imadive 0.4.2 finds new, deleted and renamed files on its own, and its update download's certificate checks no longer trust the emSign intermediates that were distrusted.

## Downloads

- **Windows 10/11**: `Imadive-0.4.2-windows-x64.exe`. Double-click it. It is not signed, so the first time Windows may show "Windows protected your PC": click **More info**, then **Run anyway**.
- **Debian, Ubuntu and Linux Mint** (Debian 12 or Ubuntu 22.04 or newer): `Imadive-0.4.2-linux-amd64.deb`. Install it with `sudo apt install ./Imadive-0.4.2-linux-amd64.deb`, then start Imadive from the applications menu.
- **Other Linux distributions (x86-64)**: `Imadive-0.4.2-linux-x86_64.AppImage`. Run `chmod +x Imadive-*.AppImage`, then start it. If it says FUSE is missing, install `libfuse2` or run it with `--appimage-extract-and-run`.
- **A Linux server** (x86-64, or ARM64 such as a Raspberry Pi 4 or 5): `Imadive-server-0.4.2-linux-x86_64.tar.gz` or `…-linux-aarch64.tar.gz`, installed by the one-line command in the [server guide](https://github.com/waiting4timeout/imadive/blob/main/docs/server.md).

Your folders, people names and index carry over from earlier versions; nothing is indexed again.

Each download can be checked: `SHA256SUMS` lists the files' checksums, and every file carries a signed record of the GitHub build it came from (`gh attestation verify <file> --repo waiting4timeout/imadive`).

## What's new

- **New, deleted and renamed files are found on their own**: every 5 minutes the gallery takes a quick look at its folders — only their dates, not every file — and scans when one of them changed, for example after Syncthing or a copy added photos, so they appear without a *Rescan*. Settings says how often; on the command-line app, `--check-every MINUTES` changes it (also `IMADIVE_CHECK_EVERY`) and `--check-every 0` turns it off.
- **Update checks are private as ever**: the download's certificate checks (rustls-webpki and webpki-roots) no longer trust the emSign intermediates that were distrusted (RUSTSEC-2026-0381, -0382, -0383).

## Fixes

- **On Windows, the periodic check no longer sees a change where there is none** — a folder listing can be behind on a folder's real date there, which would have made the gallery scan every five minutes for nothing.
