Imadive 0.4.0 finds the copies that phones make of your photos and videos, and uploads from a phone are steadier.

## Downloads

- **Windows 10/11**: `Imadive-0.4.0-windows-x64.exe`. Double-click it. It is not signed, so the first time Windows may show "Windows protected your PC": click **More info**, then **Run anyway**.
- **Debian, Ubuntu and Linux Mint** (Debian 12 or Ubuntu 22.04 or newer): `Imadive-0.4.0-linux-amd64.deb`. Install it with `sudo apt install ./Imadive-0.4.0-linux-amd64.deb`, then start Imadive from the applications menu.
- **Other Linux distributions (x86-64)**: `Imadive-0.4.0-linux-x86_64.AppImage`. Run `chmod +x Imadive-*.AppImage`, then start it. If it says FUSE is missing, install `libfuse2` or run it with `--appimage-extract-and-run`.
- **A Linux server** (x86-64, or ARM64 such as a Raspberry Pi 4 or 5): `Imadive-server-0.4.0-linux-x86_64.tar.gz` or `…-linux-aarch64.tar.gz`, installed by the one-line command in the [server guide](https://github.com/waiting4timeout/imadive/blob/main/docs/server.md).

Your folders, people names and index carry over from earlier versions: the identical-files check learns each file's new fingerprint once, and nothing is indexed again.

Each download can be checked: `SHA256SUMS` lists the files' checksums, and every file carries a signed record of the GitHub build it came from (`gh attestation verify <file> --repo waiting4timeout/imadive`).

## What's new

- **Copies that lost their details are found**: Android hands photos and videos to the browser without their location, so a photo uploaded from a phone and the same one synced to the computer were different files, and not found as copies. A JPEG is now fingerprinted by its picture — leaving out its metadata segments, but not its orientation — and an MP4 or MOV by its media, leaving out its moov box; other files as a whole, as before. Possible copies are also those with the same size in pixels and capture time, not only the same byte size; of each set, the copy with a place is kept, then the oldest.
- **Uploads from a phone are steadier**: the files chosen are no longer limited (Android's handover happens before the page can count them), and the card advises choosing a few hundred at a time; more can join an upload that is already running. While the picker hands the files over, a spinner counts the seconds waited, and the waiting can always be left; if nothing arrives, the card says the device took too long and to choose fewer at a time, and the buttons work again.
- **The upload card tells** phones that the browser loses the photos' location, and that an app syncing the camera folder keeps it.
- **On phones, the viewer's fold-details button is visible again** (Android's Chrome could let the details' scrolling hide it).
