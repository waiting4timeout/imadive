Imadive 0.4.3 no longer shows a server update that is restarting as a failed attempt.

## Downloads

- **Windows 10/11**: `Imadive-0.4.3-windows-x64.exe`. Double-click it. It is not signed, so the first time Windows may show "Windows protected your PC": click **More info**, then **Run anyway**.
- **Debian, Ubuntu and Linux Mint** (Debian 12 or Ubuntu 22.04 or newer): `Imadive-0.4.3-linux-amd64.deb`. Install it with `sudo apt install ./Imadive-0.4.3-linux-amd64.deb`, then start Imadive from the applications menu.
- **Other Linux distributions (x86-64)**: `Imadive-0.4.3-linux-x86_64.AppImage`. Run `chmod +x Imadive-*.AppImage`, then start it. If it says FUSE is missing, install `libfuse2` or run it with `--appimage-extract-and-run`.
- **A Linux server** (x86-64, or ARM64 such as a Raspberry Pi 4 or 5): `Imadive-server-0.4.3-linux-x86_64.tar.gz` or `…-linux-aarch64.tar.gz`, installed by the one-line command in the [server guide](https://github.com/waiting4timeout/imadive/blob/main/docs/server.md).

Your folders, people names and index carry over from earlier versions; nothing is indexed again.

Each download can be checked: `SHA256SUMS` lists the files' checksums, and every file carries a signed record of the GitHub build it came from (`gh attestation verify <file> --repo waiting4timeout/imadive`).

## Fixes

- **A server update that is restarting is no longer a failed attempt**: while an update installs, Settings asks for its progress every second, and the server going away to restart with the new version made it say "The last attempt failed: Failed to fetch" for good, though the update had worked. It now says *Restarting…* until the server is back, and the page reloads once it answers with the new version.
